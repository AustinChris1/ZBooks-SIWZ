## Bugs fixed during the audit

- `SignInWithZcash.tsx` was calling `onSuccess()` from render. Moved to `useEffect`.
- `useSiwz.ts` `SiwzStatus` declared `"idle"` but the hook initialised to `"addressEntry"` and never transitioned to `"idle"`. Removed the dead state.
- `scripts/e2e-memo.mjs` asserted `session.user.address.startsWith("snap:")` on the anonymous memo flow — copy-paste from the snap e2e. Fixed to `"anon:"`.
- `apps/lightwallet-rpc/src/server.mjs` imported `randomBytes` from `node:crypto` and never used it. Dropped.
- `scripts/e2e-memo-shielded.mjs` same dead import. Dropped.

## Findings worth following up

Not fixed here — flagging for later.

1. **siwz-core dead exports.** `base64Encode` (`crypto.ts`) has no callers. `UA_RECEIVER_TYPES` and `encodeP2pkh` (`address.ts`) are re-exported from the package index but unused in the workspace. Either remove or document why they're public surface.
2. **`parseAddress` HRP case-handling.** `raw.toLowerCase()` is fed to `bech32.decode`, but BIP-173 rejects mixed-case input. We're silently accepting addresses the spec wouldn't. Add a homogeneity check first.
3. **`encodeVarInt` bigint > 2³²−1 boundary.** `setBigUint64` truncates above 2⁶⁴−1; not reachable in practice, but worth a guard.
4. **`example-comments/lib/auth.ts` double-wrap.** `CredentialsProvider(SiwzProvider(...) as Parameters<typeof CredentialsProvider>[0])` — if `SiwzProvider` already returns a fully-formed provider config, wrapping again hides a type mismatch. Either fix the wrapper or `as never` it intentionally with a comment.
5. **`example-comments/lib/store.ts` write race.** Read-modify-write isn't atomic. Acceptable for a reference app; flag in the README.
6. **`gen-service-address.mjs` mode 0o600.** Ignored on Windows. Note in the script or guard the chmod.
7. **`useSiwz.trySnapSignIn`** — earlier JSDoc claimed it threw on missing `onSnapAuth`; implementation sets error state and returns `false`. Comment removed; behaviour unchanged. If callers were relying on the `throw` semantics they'll be surprised.

## Workflow recommendations

Things that would help over the remaining hackathon stretch.

### 1. Pin a "first sync" budget per UFVK in the DB

Right now wrapper-side `DEFAULT_WALLET_BIRTHDAY = 2_400_000` and the AddKeyForm pre-fills `2_800_000`. The two should derive from one shared constant (e.g. `SAFE_RECENT_BIRTHDAY` in `lib/types.ts`). Today they can drift independently.

### 2. Drop `--waitsync` on a separate metadata RPC

The reason `height` and `info` had to be removed from the wrapper was that each zingo-cli invocation re-syncs under `--waitsync`. If you ever need chain-tip / sync-block for the progress bar, a single `messages` call could parse them from the trailing status lines instead of issuing a second invocation.

### 3. Add a CI typecheck

`pnpm -r typecheck && pnpm --filter @siwz/core test` passes today. Wire it into a GitHub Action (matrix: Node 18 / 20) so regressions are caught before merge. The repo currently has no `.github/workflows/`.

### 4. Document the nginx + systemd knobs in the installer

`scripts/setup-lightwallet-vps.sh` was updated to set `MemoryMax=1200M` and the docs reference `proxy_read_timeout 600s`, but a deploy on a freshly-installed VPS still needs the user to know those numbers if they're tweaking. The installer should template the nginx vhost itself, not just trust `certbot --nginx` to produce one without the timeouts.

### 5. Add a "wipe me" admin button

For demo recording, you've been hand-editing `apps/demo/data/zbooks.json` to clear team membership. A protected admin-only `POST /api/admin/wipe` endpoint guarded by `NODE_ENV !== "production" && SIWZ_DEMO === "1"` would save the recurring hand-edit step.

### 6. Replace `window.alert`-style flows with toasts

`ConfirmDialog` covers destructive prompts. Sync-success / "added key" / "label saved" still happen silently; a tiny toast layer (Sonner is 3 KB) would give visual confirmation without a redirect.

### 7. Pin zingo-cli version in the installer

`scripts/setup-lightwallet-vps.sh` clones zingolabs/zingolib HEAD. A version bump that renames `messages` or alters its output shape will silently break the wrapper. Pin to a known-good tag and document the upgrade-test step.
